## 1. Where types are defined

Item types are **database rows**, not code constants. There is no `src/lib/constants.tsx` in this codebase (the research prompt referenced one; it does not exist).

| Concern | Location |
|---|---|
| Shape of a type | `ItemType` model — [prisma/schema.prisma:81-100](prisma/schema.prisma#L81-L100) |
| Canonical values (name, slug, icon, color, category, order) | `systemTypes` array — [prisma/seed.ts:9-17](prisma/seed.ts#L9-L17) |
| Icon string → React component | `ICON_MAP` — [src/lib/icons.ts:12-20](src/lib/icons.ts#L12-L20) |
| Read path for the app | `getSystemItemTypes()` — [src/lib/db/items.ts:83-107](src/lib/db/items.ts#L83-L107) |
| Spec / intended design | [context/project-overview.md](context/project-overview.md) §7 |

System types are seeded with `isSystem: true` and `userId: null`. The `@@unique([slug, userId])` constraint means system slugs are globally unique (since `userId` is `null` for all of them), while a user's custom type may reuse a slug under their own `userId`. Seeding is idempotent — [prisma/seed.ts:24](prisma/seed.ts#L24) looks up `{ slug, userId: null }` before creating.

`ItemType` has **no** `isPro` column. Pro gating is derived from `category === "FILE"` at render time — see [Display differences](#6-display-differences).

## 2. The 7 system types

Ordered by the `order` column as actually seeded:

| # | `order` | Name | Slug | Icon | Color | Category | URL path |
|---|---|---|---|---|---|---|---|
| 1 | 0 | Snippet | `snippets` | `Code` | `#3b82f6` blue | TEXT | `/items/snippets` |
| 2 | 1 | Prompt | `prompts` | `Sparkles` | `#8b5cf6` violet | TEXT | `/items/prompts` |
| 3 | 2 | Command | `commands` | `Terminal` | `#f97316` orange | TEXT | `/items/commands` |
| 4 | 3 | Note | `notes` | `StickyNote` | `#fde047` yellow | TEXT | `/items/notes` |
| 5 | 4 | File | `files` | `File` | `#6b7280` gray | FILE | `/items/files` |
| 6 | 5 | Image | `images` | `Image` | `#ec4899` pink | FILE | `/items/images` |
| 7 | 6 | Link | `links` | `Link` | `#10b981` emerald | URL | `/items/links` |

All icons are [Lucide React](https://lucide.dev/icons/) components. `Link` is imported as `LucideLink` in [src/lib/icons.ts:6](src/lib/icons.ts#L6) to avoid colliding with `next/link`, but is keyed as `"Link"` in the map so the DB string resolves.

## 3. Per-type detail

### Snippet — `Code` · `#3b82f6` · TEXT

**Purpose:** Reusable code blocks — hooks, utilities, config boilerplate, Dockerfiles.

**Key fields:** `title`, `description`, `content` (the code), `language` (drives syntax highlighting).

Snippets are the only type that meaningfully uses `language`. Seeded examples set it to `"typescript"` and `"dockerfile"` ([prisma/seed.ts:62](prisma/seed.ts#L62), [prisma/seed.ts:252](prisma/seed.ts#L252)).

---

### Prompt — `Sparkles` · `#8b5cf6` · TEXT

**Purpose:** AI prompts, system messages, and reusable prompt templates — the "AI-first developer" use case.

**Key fields:** `title`, `description`, `content` (the prompt body, typically Markdown). `language` is left `null`.

Seeded prompts use Markdown headings, bold, and fenced `[PASTE CODE HERE]` placeholders — so the editor for this type needs Markdown rendering, not code highlighting. Target of the planned `/api/ai/optimize-prompt` Pro feature.

---

### Command — `Terminal` · `#f97316` · TEXT

**Purpose:** Shell/CLI commands and multi-step terminal recipes.

**Key fields:** `title`, `description`, `content` (the command text). `language` is `null` in seed data.

Content is often multi-line with `#` comments acting as sub-headings for a group of related commands ([prisma/seed.ts:309-322](prisma/seed.ts#L309-L322)), or a single chained one-liner ([prisma/seed.ts:279](prisma/seed.ts#L279)).

---

### Note — `StickyNote` · `#fde047` · TEXT

**Purpose:** Free-form Markdown notes, documentation, explanations, course material.

**Key fields:** `title`, `description`, `content`.

The only text type with **no seeded examples** — the `notes` type row exists, but the demo dataset has zero Note items.

---

### File — `File` · `#6b7280` · FILE · **Pro**

**Purpose:** Arbitrary file attachments (context files, templates, PDFs, archives) stored in Cloudflare R2.

**Key fields:** `title`, `description`, `fileUrl` (R2 URL), `fileName` (original filename), `fileSize` (bytes). `content` and `url` stay `null`.

Not seeded — R2 is not yet wired (`R2_*` env vars are listed as planned). The intended flow is presigned-URL upload direct to R2, then the server persists the three `file*` fields onto the `Item`.

---

### Image — `Image` · `#ec4899` · FILE · **Pro**

**Purpose:** Screenshots, diagrams, design references.

**Key fields:** identical to File — `fileUrl`, `fileName`, `fileSize`.

Structurally indistinguishable from File at the schema level; the difference is presentational (an Image item should render a thumbnail/preview, a File item an icon + filename + size). Not seeded.

---

### Link — `Link` · `#10b981` · URL

**Purpose:** Bookmarked docs, references, tools.

**Key fields:** `title`, `url`. Notably, **all 6 seeded links set only `title` + `url`** — no `description`, no `content` ([prisma/seed.ts:281-292](prisma/seed.ts#L281-L292), [prisma/seed.ts:390-413](prisma/seed.ts#L390-L413)).

This makes Link the sparsest type and the one most in need of enrichment (favicon, page title fetch, OG preview) — none of which exists yet.

## 4. Classification: TEXT vs URL vs FILE

The `ContentCategory` enum ([prisma/schema.prisma:75-79](prisma/schema.prisma#L75-L79)) partitions all 7 types by **which content column they populate**:

| Category | Types | Populated column(s) | Null columns |
|---|---|---|---|
| `TEXT` | Snippet, Prompt, Command, Note | `content` (`@db.Text`) | `url`, `fileUrl`, `fileName`, `fileSize` |
| `URL` | Link | `url` | `content`, `file*` |
| `FILE` | File, Image | `fileUrl`, `fileName`, `fileSize` | `content`, `url` |

Consequences of this design:

- **All content columns are nullable.** `Item` is a single wide table with a discriminator (`typeId → type.category`) rather than per-type tables. Nothing in the schema enforces "a TEXT item must have `content`" — that invariant has to live in validation code (Zod, per coding standards) when item CRUD is built.
- **Category is the gating axis**, not the type. `FILE` ⇒ Pro. See below.
- **4 of 7 types are TEXT**, so the text path is the dominant one and the only one currently exercised by seed data.

## 5. Shared properties

Every item, regardless of type, carries the same envelope ([prisma/schema.prisma:104-140](prisma/schema.prisma#L104-L140)):

| Field | Type | Notes |
|---|---|---|
| `id` | `String` | cuid |
| `title` | `String` | **required for all types** — the only required content-ish field |
| `description` | `String?` | optional subtitle; unused by Link seed data |
| `language` | `String?` | nominally shared, meaningful only for Snippet |
| `isFavorite` | `Boolean` | default `false`; indexed as `[userId, isFavorite]` |
| `isPinned` | `Boolean` | default `false`; indexed as `[userId, isPinned]` |
| `lastUsedAt` | `DateTime?` | indexed as `[userId, lastUsedAt]`; drives "Recently used" |
| `aiSummary` | `String?` | Pro, planned — not yet written by anything |
| `aiTags` | `String[]` | Pro, planned — kept separate from user tags so they can be accepted/dismissed |
| `createdAt` / `updatedAt` | `DateTime` | |
| `userId` → `user` | relation | `onDelete: Cascade` — deleting a user removes their items |
| `typeId` → `type` | relation | **no cascade** — an `ItemType` cannot be deleted while items reference it |
| `tags` | `ItemTag[]` | many-to-many via join table; `Tag.name` is globally unique |
| `collections` | `ItemCollection[]` | many-to-many; an item can live in several collections |

**Shared behaviors that are type-agnostic:** favoriting, pinning, tagging, collection membership, recency tracking, search, and the AI fields. Nothing in the schema restricts any of these by type.

## 6. Display differences

### Color and icon are data-driven everywhere

No component hardcodes a type. Every surface reads `type.icon` (string) through `ICON_MAP` and `type.color` (hex) as an inline style, with `File` as the fallback icon when a string isn't in the map:

| Surface | Icon use | Color use |
|---|---|---|
| `ItemCard` badge | `Icon` at `h-3 w-3` | text `type.color`, background `${color}20` (12.5% alpha) — [ItemCard.tsx:21-27](src/components/dashboard/ItemCard.tsx#L21-L27) |
| Dashboard "Recent" row | leading icon tinted `type.color` | same `${color}20` chip — [dashboard/page.tsx:127-140](src/app/dashboard/page.tsx#L127-L140) |
| Sidebar nav item | `ICON_MAP[type.icon] ?? File` | `iconColor={type.color}` — [Sidebar.tsx:373-375](src/components/layout/Sidebar.tsx#L373-L375) |
| `CollectionCard` type chips | mini icon per distinct type in the collection | `${color}20` tile background — [CollectionCard.tsx:44-56](src/components/dashboard/CollectionCard.tsx#L44-L56) |
| `CollectionCard` border | — | `${dominantColor}50` from the collection's most common item type — [CollectionCard.tsx:28](src/components/dashboard/CollectionCard.tsx#L28) |

The `${color}20` / `${color}50` suffix trick appends an 8-digit-hex alpha channel to the stored 6-digit color, which is why colors are stored as plain hex strings rather than CSS variables.

### Pro gating is by category, in the sidebar only

[src/components/layout/Sidebar.tsx:368-378](src/components/layout/Sidebar.tsx#L368-L378):

```ts
const isPro = type.category === "FILE"
// → count hidden, "PRO" badge shown instead
count={isPro ? null : type.count}
badge={isPro ? "PRO" : undefined}
```

So File and Image render a `PRO` badge in place of their item count. This is the **only** Pro gate in the codebase today — there is no `isProUser()` helper yet ([src/lib/features.ts](src/lib/features.ts) exports only `isEmailVerificationEnabled()`), and no API-level enforcement, because item CRUD doesn't exist yet.

### Content rendering does *not* branch on type yet

This is the significant gap. [ItemCard.tsx:31-35](src/components/dashboard/ItemCard.tsx#L31-L35) renders a `<pre>` preview **if `content` exists**, and nothing otherwise:

- TEXT items → first 180 chars in a monospace block, `line-clamp-3`
- Link items → **no preview at all** (`content` is null; `url` is never read by the card)
- File/Image items → would also render nothing (`fileUrl`/`fileName`/`fileSize` are not in `ItemCardProps`)

Likewise `ItemWithMeta` ([src/lib/db/items.ts:13-25](src/lib/db/items.ts#L13-L25)) selects `content` and `language` but **not** `url`, `fileUrl`, `fileName`, or `fileSize` — so URL and FILE payloads never reach the UI. `language` is carried through the data layer and the card's props but is never rendered anywhere.

**Implication for item CRUD:** the card and the query layer both need per-category branches (text preview / URL + favicon / file thumbnail + size) before Link, File, or Image items are usable.

## 7. Discrepancies found

Worth resolving before building item CRUD:

1. **`src/lib/constants.tsx` does not exist.** The research prompt lists it as a source. Type constants live in [prisma/seed.ts](prisma/seed.ts) (values) and [src/lib/icons.ts](src/lib/icons.ts) (icon map). If a shared constants module is wanted, it doesn't exist yet.

2. **Ordering differs between the spec and the seed.** [context/project-overview.md](context/project-overview.md) §7 lists Snippet, Prompt, **Note, Command**, Link, File, Image. The seed uses Snippet, Prompt, **Command, Note**, File, Image, Link — matching the "Stats & Sidebar" history entry, which explicitly reordered them. **The seed is correct**; the overview table is stale.

3. **Singular vs plural names.** Seeded `name` values are singular (`"Snippet"`), so badges read "SNIPPET" while the sidebar shows the same singular label where a plural nav label would read better. The stale [src/lib/mock-data.ts](src/lib/mock-data.ts) used plurals.

4. **[src/lib/mock-data.ts](src/lib/mock-data.ts) is dead code.** Nothing imports it (verified by grep). Its `mockItemTypes` carries the old ordering (`order: 1-7`, Links at 5) and plural names, so it is actively misleading as a reference.

5. **No Note items in seed data.** The Note type has no coverage in the demo dataset, unlike every other TEXT type.

6. **`Item.language` is write-only.** Set by the seed, selected by the query layer, typed in `ItemCardProps` — never rendered. Syntax highlighting is still unimplemented.
